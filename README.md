# Alfred Travel Website V2

## Purpose

Website V2 is the public-facing expression of the Alfred Travel webapp.

The existing webapp styling and visual language are the source of truth because that is the experience users already respond positively to. The website should feel like the same Alfred product, not a separate marketing site or a generic travel template.

## Core instruction

Audit and redesign the public Alfred Travel website against the webapp baseline. Capture both:

1. UI/UX and visual recommendations
2. Exact content and copy recommendations

The work must be page-by-page and should identify what to keep, change, remove, consolidate, and implement first.

## Desired experience

The website should feel:

- traveller-first
- calm
- premium
- structured
- useful
- trustworthy
- product-led
- visually consistent with the webapp

The website should communicate that Alfred helps travellers move from trip idea to a clear, editable, booking-ready plan.

## Design baseline

Use the webapp as the design reference for:

- overall visual mood
- color palette and accent usage
- typography hierarchy
- spacing and density
- cards and surfaces
- button and CTA treatment
- product-preview framing
- trust and status cues
- mobile/responsive behavior

Do not invent a separate visual direction, rely on generic Canva templates, or create a disconnected luxury-travel aesthetic.

## Content principles

Emphasise:

- structured itineraries
- editable plans
- family and multi-city planning
- route and timing confidence
- booking readiness
- practical travel decisions
- visible support
- calm control over trip complexity

Reduce or remove from primary marketing surfaces:

- generic travel clichés such as “Start your journey” and “Discover your next adventure”
- excessive AI terminology
- unexplained technical model references
- over-optimised SEO phrasing
- “Travel 3.0” language
- blockchain/reward messaging unless it is specifically relevant to a dedicated page
- claims that are not clearly supported by the product

## Trust and support rules

Keep support consistently visible across the site:

- Support Center
- Help & FAQ
- account support
- privacy and deletion pathways

Avoid Contact Us links that only send users back to the homepage. Footer and navigation labels should remain consistent across every page.

## Pages in scope

1. Homepage
2. About / Company
3. Products / Features
4. Itineraries index
5. Individual itinerary pages
6. Compare index
7. Individual competitor comparison pages
8. Blog index
9. Blog article template and article content style
10. FAQ
11. Support / account deletion
12. Global navigation
13. Global footer
14. Responsive/mobile behavior
15. SEO metadata and structured content where it affects user clarity

## Required recommendation format

For each page, capture:

- current purpose and observed issues
- how it should align with the webapp
- UI/UX changes
- visual changes
- content to keep
- content to remove or de-emphasize
- exact replacement copy where possible
- CTA recommendation
- trust/support recommendation
- SEO/title/meta direction where relevant
- implementation priority

## Implementation approach

Recommended order:

### Phase 1 — foundation

1. Define shared visual tokens from the webapp
2. Align global navigation and footer
3. Rewrite the homepage
4. Rewrite support and FAQ surfaces
5. Rewrite About / Company

### Phase 2 — product discovery

6. Rewrite Products / Features
7. Rewrite Compare index and competitor pages
8. Rewrite Itineraries index
9. Standardise individual itinerary pages

### Phase 3 — authority and content

10. Rewrite Blog index
11. Standardise blog article templates and tone
12. Review metadata, canonical URLs, schema, and internal links

## Working rule

The website should become the public-facing story of the webapp:

> Same Alfred product. Same visual confidence. Clearer public explanation.
